# Research paper kit

Everything needed to write up the Age-Gated Profile Recommender, in one folder. Nothing
here is the paper itself; these are the facts, tables, figures and cautions to write it from.

| File | Use it for |
|---|---|
| `01_outline.md` | Section-by-section plan, with what goes in each and where the material is |
| `02_method.md` | The system described precisely: rating rules, gate checks, formulas, diagrams |
| `03_results.md` | Every measured table, ready to copy, with how each number was produced |
| `04_claims_and_limitations.md` | What the evidence supports, what it does not, and threats to validity |
| `05_related_work.md` | The techniques this builds on and the papers to cite for each |
| `references.bib` | BibTeX for those papers. **Verify every entry before submitting** |
| `06_reproducibility.md` | Environment, seeds and the exact commands behind each table |
| `figures/` | The six charts (PNG), with captions in `03_results.md` |
| `data/` | The raw CSV and JSON behind the tables and charts |

## Three things to keep straight while writing

1. **All data is synthetic.** Items, profiles and moderator decisions were generated by a
   seeded script. No result says anything about real users or real harmful content.
2. **The language model was never part of a measured result.** The evaluation runs on
   constructed pipeline outputs; the one live run used a rule-based stand-in for the model.
3. **Several results are weak or negative**, and one follows from how the data was built.
   `04_claims_and_limitations.md` lists them. A paper that reports them plainly is stronger
   than one that hides them, and a reviewer who reruns the code will see them anyway.

## Where the numbers come from

`figures/` and `data/` are copies of files in `recommendation/results/`, taken on
2026-10-09. If you rerun the evaluation, copy them again. The source of truth for results
is `recommendation/results/RESULTS.md`.
